# SIG/BG Feature Explorer — mk1

Which input variables separate the HSS signal from background in the ATLAS Run-3 MSVtx long-lived-particle search, in the endcap and the barrel? And which of them only appear to?

This repo does two things:

1. **Code you can run yourself.** `pipeline/kj_sigbg_mk5.py` scores every column that the background file and the six signal mass-point files have in common. `site_builder/build_site.py` turns the output into a static website.
2. **The results we have so far,** published as that website (GitHub Pages). Every plot can be viewed in the browser and downloaded as a PDF: per feature, per split, or as one PDF of whatever the Graphs page is showing.

> **Read the Findings page first.** The background sample is data selected at `htmiss_NOSYS` < 40 GeV, and every signal event has `htmiss_NOSYS` ≥ 40 GeV. This split is by design. It means that any variable tied to HTmiss or jet activity separates the two files *because of the selection*. Also, 43% of the background has no jets at all, while signal has essentially none. The pipeline flags these features, and the site explains which rankings to trust.

The site opens in a dark theme that matches the project art. The **light** button at the bottom of the left panel switches to a white work-document theme, and the choice is remembered in that browser.

### Layout

`index.html` is a shell: a fixed **left panel** and one **iframe** that shows the chosen view (`app.html#/...`). The address bar keeps the view (`index.html#/sb/endcap|jet_n_NOSYS`), so links and the back button work. "open in new tab" at the bottom of the panel opens the current view on its own. On a phone the panel folds into a **menu** button.

The panel opens on four options:

| option | what it shows |
|---|---|
| **Features · Barrel – Endcap** | every feature in a list (sort by \|D barrel − D endcap\|, D endcap, D barrel, shape D; filter by where it separates), and the selected feature's two barrel-vs-endcap pages: *shape* and *endcap \| barrel separation* |
| **Features · Signal – Background** | every feature ranked by KS D in endcap / barrel / all, with the Rankings filters, and the selected feature's pages: overview, endcap, barrel, all |
| **Suggested NN groupings · Barrel – Endcap** | the pipeline's candidate input sets P0–P3 (block D) per network and region, every member with its barrel-vs-endcap page |
| **Suggested NN groupings · Signal – Background** | the same sets, every member with its signal-vs-background page in the chosen region, the surrogate AUCs (with the change vs P0) and what was added / dropped vs P0 |

Every plot view has:
- **A large variable banner** above the plot, coloured by region (endcap blue, barrel orange, both grey, barrel–endcap split), plus a sticky name strip on the plot itself, so the variable is always on screen.
- **A page map**: a schematic of the PDF page with every panel code (1a, 1b, 2a … ; a = left column, b = right column; "legend" = mk5's legend column) and what each panel shows. Hover a panel on the map, a line of the list, or the plot itself to outline it; click to zoom into that panel.
- **PDF links**: open the original vector PDF at that page, download the whole feature PDF, download the PNG. Group views also build one PDF of the whole group in the browser (served site only, see below).
- **Keyboard**: ↑ / ↓ (or j / k) steps through the feature list.

The site has these pages: Overview · **Graphs** · Findings · Rankings · Feature · Barrel vs endcap · Correlation · Prototypes · Exclusions · **PDF browser** · Summaries · Metrics · Files & code · Archive.

**Graphs** is the quickest way to see every plot. Pick one or more splits:

| group | split | the page shown for every feature |
|---|---|---|
| signal vs background | endcap | each mass point, combined signal and background alone, endcap (raw + normalized) |
| | barrel | the same, barrel |
| | all | the same, both regions together |
| | endcap \| barrel | endcap and barrel side by side on one page (normalized) |
| barrel vs endcap | shape | background barrel vs endcap, and signal barrel vs endcap |

One split shows a grid (sizes S/M/L). Several splits show one row per feature with the splits side by side. Search, sort and the Rankings filters (htmiss-linked, non-physics, jet-dependent, NN-list, "separates") apply, and the address bar keeps the selection (`#/graphs/sb_endcap+sb_barrel`). Click a plot to enlarge it, then use ← → to step through everything on screen. Downloads:

- **Per split:** each split tile links to `bundles/<run>/<split>.pdf`, which holds that split's page from every feature in rank order, bookmarked by feature name. These work offline too.
- **This view:** "Download this view as one PDF" builds a PDF in your browser from the original vector pages, in the order shown and with the filters applied. It uses pdf-lib from a CDN and has to read the PDFs, so it only works when the site is served (GitHub Pages, or `python -m http.server` in the repo and then `http://localhost:8000`), not when you open `index.html` straight from disk.
- **Per feature:** "PDF · S/B" and "PDF · B/E" on each row, and "PDF p<N>", which opens the source PDF at that page.

**PDF browser** (was "All plots") shows every page of every PDF the work produced, PDF by PDF: 608 pages from the current run and 4,234 from the archived runs, 4,842 in total. You can browse by source and PDF, or search page titles (feature, region, selection) across a whole source.

## Quick start: view the results

- **Locally:** open `index.html` in a browser. It needs no server. Fonts and the math rendering load from a CDN, so they only appear when you're online; the page works without them.
- **Online:** enable GitHub Pages under Settings → Pages: source "Deploy from a branch", branch `main`, folder `/ (root)`. This works on a free account as long as the repo is public.

## Run it yourself

You need Python 3.10 or newer and your own copy of the seven CSVs. **The data is not in this repo.**

```bash
git clone https://github.com/<you>/<this-repo>.git
cd <this-repo>
python -m venv .venv
#   Windows:      .venv\Scripts\activate
#   macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
```

Tell the pipeline where the data is. The first of these that it finds wins:

1. `--data <folder>` on the command line
2. `pipeline/config.txt`: copy `config_example.txt` to `config.txt` and set `DATA = <folder>`
3. the environment variable `KJ_SIGBG_DATA`

The folder must hold:

| file | role |
|---|---|
| `DataHTMissLow_train_data24_cleaned.csv` | background (data) |
| `HSS_mH125_mS15_ct580_cleaned.csv` | signal, mH = 125 GeV, mS = 15 GeV |
| `HSS_mH125_mS55_ct5320_cleaned.csv` | signal, 125 / 55 |
| `HSS_mH200_mS50_ct1255_cleaned.csv` | signal, 200 / 50 |
| `HSS_mH400_mS100_ct1610_cleaned.csv` | signal, 400 / 100 |
| `HSS_mH600_mS150_ct3310_cleaned.csv` | signal, 600 / 150 |
| `HSS_mH1000_mS275_ct2399_cleaned.csv` | signal, 1000 / 275 |

Then run:

```bash
python pipeline/kj_sigbg_mk5.py --round 1            # writes pipeline/out_sigbg_mk5_r1/   (about 5–10 min)
python tools/selection_check.py --out pipeline/out_sigbg_mk5_r1
```

Useful flags:
- `--block BC` runs only some of the blocks.
- `--no-plots` writes tables only, which is fast.
- `--top 20` writes feature PDFs for the top 20 only.
- `--png` also writes PNGs.

### Publish a run on the site

```bash
# copy the finished run folder into results/  (the folder name becomes the run name on the site)
#   Windows:      xcopy /E /I pipeline\out_sigbg_mk5_r1 results\mk5_r1
#   macOS/Linux:  cp -r pipeline/out_sigbg_mk5_r1 results/mk5_r1
python site_builder/build_site.py                    # renders every PDF page (incremental), writes bundles/ and data/*.js
```

Open `index.html`. The run picker at the bottom of the left panel lists every folder in `results/`; the newest name (e.g. `mk5_r1`) opens by default. A run whose folder name starts with `mk5` gets the mk5 page map (legend column). Commit `results/`, `data/`, `img/` and `bundles/`, then push.

The builder prints progress per run and per PDF. Rendering about 600 PDF pages takes around a minute the first time, and later runs only re-render pages that changed. The five split bundles (about 24 MB per run) are rewritten only when their page list or a source PDF changes; `bundles/<run>/manifest.json` records what each one was built from. The splits are defined in `SPLITS` at the top of `build_site.py`. Use `--force` to re-render everything and `--dpi 130` for sharper images. Archived runs render at `--archive-dpi 90`, which takes about 5 minutes the first time; `--skip-archive-plots` leaves them out.

## The editable file: `pipeline/exclude_features.txt`

This is the one input you're meant to change between runs:

- Put one exact column name or glob per line, e.g. `trigPassed_*` or `msvtx_nRPC*`.
- `#` starts a comment, and matching is case-sensitive.
- The pipeline leaves those columns out of every block, and lists what each line removed in `results/<run>/00_common/excluded_report.txt` under **user**. If a line removed nothing, it doesn't match any column name.
- The script already removes these, so don't repeat them (`HARD_EXCLUDE` in `kj_sigbg_mk5.py`): labels, NN scores, all weights and scale factors, run/event/channel numbers, `htmiss_NOSYS`, `met_met_NOSYS`, and the region selectors `msvtx_inBarrel_NOSYS` / `msvtx_inEndcaps_NOSYS`.
- The site's **Exclusions** page can't write to your disk. It lets you pick features (one-click "add all htmiss-linked", "add drop suggestions", and so on), shows a preview, and **downloads** a new `exclude_features.txt` to drop into `pipeline/`.

## What the pipeline computes

| block | output folder | what it answers |
|---|---|---|
| 00 common | `00_common/` | Data-health unit test (the HTmiss split), column inventory, duplicate columns, exclusions, region audit |
| A | `A_barrel_vs_endcap/` | Where does each feature separate: endcap, barrel, both, neither? How different are the barrel and endcap shapes? |
| B | `B_mc_vs_data/` | KS separation per feature, region and mass point; scores for the current NN lists; strong features the lists don't use |
| C | `C_correlation/` | Spearman correlation on background, redundancy blocks, NN1–NN2 cross-correlation |
| D | `D_prototypes/` | Candidate input sets P0–P3, scored with a gradient-boosted surrogate (it nominates; GAMBIT decides) |
| E | `E_selection/` | How the samples were selected: HTmiss edge, jet counts, MET edge (from `tools/selection_check.py`) |
| GAMBIT | `gambit_inputs/` | Unit tests, candidate pools, blocks, drop suggestions, prototype lists |

### Metrics in one line each
- **KS distance** $D=\sup_x|F_s(x)-F_b(x)|$: the best single cut, i.e. the largest achievable signal efficiency minus background efficiency.
- **Equal-weight combination** $F_{eq}=\frac{1}{M}\sum_m F_m$: each mass point counts the same. The **pooled** version weights each mass point by its event count.
- **Noise floor** $D_{crit}=1.36\sqrt{1/n_s+1/n_b}$: the 95% KS critical value.
- **Separates** when $D\ge\max(0.20,\,2D_{crit})$. **Strong** at $D\ge0.50$. **Suspicious** when any single mass point reaches $D\ge0.99$.
- **Redundancy block**: $|\rho_S|\ge0.9$ on background with every member.
- **dCor**: distance correlation between the NN1 and NN2 surrogate scores on background.

The **Metrics** page on the site has the full definitions. It reads the thresholds from the script, so it always matches the code.

## The full development history (`results/archive/`, `pipeline/archive/`)

The repo contains the whole iterative development, not just the latest version. The **Archive** page shows it as a timeline.

| version | script | runs kept | status |
|---|---|---|---|
| mk1 | `pipeline/archive/kj_sigbg_mk1.py` | `out_sigbg_r1`: first KS pass, three 193-page PDFs | superseded by mk4 block B |
| mk2 | `pipeline/archive/kj_sigbg_mk2.py` | `out_sigbg_mk2_r1`: cut on htmissScalar ≥ 40 GeV | kept and relabelled: the "after cut" background is the 2+-jet background only. Its `bkg_split.csv` feeds the site's **jet-dependence** test |
| | | `out_sigbg_mk2_r1_ht40`: cut on htmiss_NOSYS ≥ 40 GeV | null result: no background survives, which is how the disjoint selection was found |
| | | `out_sigbg_mk2_r1_ht40_met20`: htmiss ≥ 40 and met_met ≥ 20 GeV | null result; its selection report shows the **MET edge** (signal met_met ≥ 20.07 GeV) |
| mk3 | `pipeline/archive/kj_sigbg_mk3.py` | `out_sigbg_mk3_r1`: tables only | superseded by mk4 blocks 00 and B |
| mk4 | `pipeline/archive/kj_sigbg_mk4.py` | `results/mk4_r1` | shown until `mk5_r1` exists; legends inside the panels can cover data |
| mk5 | `pipeline/kj_sigbg_mk5.py` | run it: `results/mk5_r1` | **current**: mk4 analysis, legends in their own column, panel codes on every panel |
| checks | `pipeline/archive/ht_edge_check.py` | transcribed into `results/mk4_r1/E_selection/` | superseded by `tools/selection_check.py` |

Two results exist only because of mk2, and the main pages use them:
- **Background split.** Inside the background, events with 0–1 jets are compared against events with 2+ jets. Features that differ (D ≥ 0.2) depend on jet activity. They carry a **jet-dep** chip in Rankings, a row on each feature page, and a table in Findings §5.
- **MET edge.** Findings §4.

The archived scripts still contain their hard-coded data path. To rerun one, edit the `DATA = ...` line near the top. Edit `results/archive/archive_index.json` to change the Archive page text, then rerun the site builder.

## Data and clearance

- The input CSVs never go into this repo. `config.txt` is git-ignored.
- `results/`, `data/`, `img/` and `bundles/` contain distributions and scores computed from ATLAS data and simulation. **Make sure they are cleared for public release before you push them to a public repo.** If only the code may be public, delete `results/`, `data/`, `img/` and `bundles/` before committing. The code still runs, and anyone with access to the files can rebuild the site locally.

## Provenance

- `pipeline/kj_sigbg_mk5.py` = mk4's analysis, unchanged, with a new plot layout: each row of panels has its own legend column, so no legend covers data; every panel title starts with its code (1a, 1b, …); the summary bar chart's legend sits above the axes. Output goes to `out_sigbg_mk5_r<N>`.
- `pipeline/archive/kj_sigbg_mk4.py` produced `results/mk4_r1`; compared with the original it only reads the data path from `--data` / `config.txt` / `KJ_SIGBG_DATA`.
- `results/mk4_r1/E_selection/` was transcribed from console checks run on 2026-10-26. Run `tools/selection_check.py` to regenerate it in full, which adds per-region and per-sample jet counts.
